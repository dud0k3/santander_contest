
# SANTANDER Customer Transaction Prediction - https://www.kaggle.com/competitions/santander-customer-transaction-prediction/overview

Santander - компания была спонсором моей любимой футбольной лиги(захотелось вникнуть именно в этот контест)

Нужно предсказать совершит клиент транзакцию или нет (таргеты - 1 и 0 соответсвенно)

# 1) EDA 
- В данных нет пропусков
- Сильный дисбаланс классов (1 к 9)
- Корреляции между признаками практически нет => простое перемножение фичей ничего не даст

# 2) version 1 - Baseline 
- Light GBM
- 5 фолдов
- Базовая модель показала хороший результат на public score(roc_auc = 0.89) и такой же на private score

# 3) version 2 - Feature engineering
- Мы создаем новую колонку var_0_freq. Если значение 11.5342 встречается в данных 50 раз, модель получает явный признак со значением 50

- Раз перемножать признаки не имеет смысла - будем получать ноль, то будем считать суммы, средние и т.д. по каждому объекту и из них делать выводы

- Модель показала результаты лучше baseline | private score (roc_auc = 0.89259), public_score (roc_auc = 0.89596)

# 4) version 3 
- XGBoost
- CatBoost
- roc_auc_XGB = 0.90437(на паблик и приват скоре roc_auc порядком меньше)
- roc_auc_Catboost = 0.90870(на паблик и приват скоре roc_auc порядком меньше)

# 5) Сделали подбор гиперпараметров в version 2.1 для LGBM 
- Лучшие параметры: {'subsample': 0.7, 'num_leaves': 15, 'min_child_samples': 100, 'max_depth': 5, 'learning_rate': 0.1, 'colsample_bytree': 0.8}
- roc_auc = 0.89426
- c подбором гиперпараметров были определенные проблемы (сперва попробовал optuna , но кол-во деревьев было очень большим и долгим , я решил использовать randomizerCV - так как его было много в работах других ребят в соревновании и optuna особого буста в скоре бы не дала)

# 6) version 4 - blanding
- Использовал комбинацию Catboost,XGB,LGBM
- каждую из моделей брали с определенным весом(сперва попытался выбрать веса каждой модели на рандом потом сделал перебор с помощью функции - результат улучшился)
- в итоге получили самый высокий скор из всех попыток (private_score = 0.89407 ,puclic_score = 0.89652)

# 7) Результат меня не устроил и я дополнительно покопался в работах и описании контеста 
- Создатели датасета специально добавили большое кол-во искусственных данных (что путало модели)
- Я разделил искусственные и настоящие данные (0 и 1). В коде был проведен поиск уникальных значений в тестовой выборке. Если значение столбца встречается в test ровно 1 раз, то строка гарантированно является настоящей
- Для каждого из 200 фичей создан бинарный признак var_i_has_dup (1 - значение встречается в реальных данных больше одного раза, 0 - если значение уникально)
- Этот подход помог модели разделить шум и настоящие транзакции
- Я обучил LGBM,CatBoost,XGB - но лучший результат дал LGBM , roc_aur_puclic = 0.90892, roc_auc_private = 0.90516
- Исходя из кол-во пользователей ~9000 участников мой результат находится примерно в 10-15% лучших работ
